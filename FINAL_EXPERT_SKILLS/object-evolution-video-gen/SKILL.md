# Object Evolution Video Gen

## Overview
本技能专为展示对象演变过程的视频设计，严格遵循V3全局标准规范，以**时间线叙事为核心**，根据用户提供的多阶段参考图、演变描述，自动生成逻辑连贯、特征一致的演变视频。核心优势在于通过全局对象特征一致性保障、阶段间自然过渡机制，确保演变过程真实自然，无突兀跳变。

---

## 标准Plan.json Schema
```json
{
  "demand": {
    "original_text": "用户原始需求全文 + 演变过程描述全文（必须）",
    "demand_list": ["结构化提取的演变要点、阶段划分、变化要求、风格要求（必须，按时间顺序排序）"],
    "original_assets": ["用户提供的各阶段参考图片路径（可选）"],
    "generated_assets": [
      "对象核心特征参考图（必须，统一对象全程特征）",
      "各演变阶段参考图（必须，缺失阶段补全生成）",
      "整体风格参考图（必须，统一色调/光影/风格）",
      "其他生成的辅助资产路径"
    ]
  },
  "shots": [
    {
      "shot_id": "镜头编号（必须，从1开始递增）",
      "description": "镜头详细描述，必须明确对应哪个演变阶段、变化过程（必须）",
      "duration": "时长（秒，范围为4-15，必须）",
      "lines": "旁白/解说内容（可选）",
      "subtitle": "字幕内容（可选，对应阶段说明/时间节点）",
      "shot_type": "连续镜头：与上一个阶段演变连续/切分镜头：阶段之间跳切（必须）",
      "require_assets": ["需要关联的资产ID（必须包含：当前阶段初始参考图 + 下一阶段参考图 + 对象特征参考/风格参考）"],
      "is_completed": "bool（必须，标记镜头是否生成完成）"
    }
  ]
}
```

## Workflow
### Step 0: 获取输出目录
使用`get-output-dir`技能获取输出目录保存中间文件和最终结果
初始化`plan.json`文件（记录`demand.original_text`）

### Step 1: 需求与资产盘点
- **理解用户需求**：提取视频时长、分辨率、风格要求、演变类型（生长/变化/时间流逝等）、配音需求、特殊效果要求
- **提取文本素材**：收集用户提供的演变过程描述、时间节点、变化规则，记录到`demand.original_text`
- **盘点用户资产**：收集用户提供的各阶段参考图片，按时间顺序整理，记录到`demand.original_assets`
- **核心参数确认**：确认演变阶段数量、每个阶段的关键状态、过渡效果要求、是否需要旁白解说
- **结构化输出演变要点**：演变对象、阶段划分、每个阶段的状态特征、变化规则、时间节点，按时间顺序排序记录到`demand.demand_list`
- **提取风格要求**：整体色调、光影、画质风格、运镜要求

### Step 2: 资产缺口评估与补全
- **强制分析现有资产（必须执行）**：
  使用`vision-understanding`逐一分析用户提供的各阶段参考图，提取：
  - 对象核心特征（颜色/形状/结构/材质）
  - 当前阶段状态
  - 风格信息（色调/光影/质感）
  未执行该分析不得进入后续步骤

- **盘点与缺口判断（必须执行）**：
  基于plan.json中的阶段划分，对比现有资产，判断：
  1. 是否缺少某些演变阶段参考图
  2. 是否缺少统一的对象特征定义
  3. 是否缺少统一风格参考

- **生成全局一致性资产（必须补全）**：
  若存在任一缺口，必须使用`image-gen`补全，不得直接进入视频生成：
  1. 对象核心特征参考图：统一对象全程特征
  2. 各演变阶段参考图：补全缺失阶段
  3. 整体风格参考图：统一色调/光影/风格
  **注意：生成的资产之间应该具有一致性，不应风格差异过大**

- 所有生成资产记录到`demand.generated_assets`，作为后续所有镜头生成的核心参考

### Step 3: 演变脚本规划（生成plan.json）
- 基于时间线叙事文案拆分镜头，单镜头时长控制在4-15秒之间，每个镜头对应一个演变阶段或一段连续变化过程
- 为每个镜头规划：
  - `description`：明确描述当前阶段的对象状态、变化过程，必须承接上一个镜头的结束状态，保证演变逻辑连贯
  - 时长、旁白内容、字幕内容（时间节点/阶段说明）、镜头类型
- 生成完整`plan.json`文件，包含所有镜头的详细信息

### Step 4: 逐镜头视频生成
1. 读取最新`plan.json`全量内容并复述
2. 动态生成视频提示词，使用`video-gen`进行音画同出的视频生成：
  - 每个镜头生成时必须引入：
    - 全局对象特征/风格/当前阶段参考资产/**对应关键帧**
    - 连续镜头必须额外引入上一个已生成的镜头的**尾帧**作为参考，保证演变过程衔接自然（使用`extract-video-frame`技能截取）
    - 如果包含台词/旁白：必须在**视频提示词内明确标注**说话人属性、音色、台词内容（但请声明无字幕）
    - **在生成第n+1个片段的时候，必须使用n个片段的音频作为参考[使用`split-audio`技能来分割音频], 以及第n个片段的视频，来保持角色，场景，音频等元素的高度一致，避免不协调的情况。并且你需要在prompt里写明: 参考[音频1]的音色, 背景音乐，保持音频等元素的高度一致，剧情连贯，禁止重复音频里说话的内容。**
3. 生成完成后使用`vision-understanding`检查：
   - 对象核心特征是否与参考图一致，无特征漂移
   - 演变过程是否符合描述，过渡自然流畅
   - 风格、色调是否与整体参考一致
   - 不符合要求的重新生成
4. 生成完成后更新shot状态到`plan.json`

### Step 5: 后期合成
1. 读取`plan.json`检查所有shot生成完成情况
2. 逐条检查`plan.json`的`demand.demand_list`是否完成
3. 按要求拼接并导出最终视频
4. 对最终视频使用`vision-understanding`技能进行理解检查质量，若不合格则进行对应返工或补充

## Dependent Sub-Skills
- `vision-understanding`：分析参考图内容、提取对象特征、检查视频片段一致性
- `image-gen`：生成全局参考资产、补全缺失演变阶段参考图，请使用`gpt-image-2`模型
- `video-gen`：生成（有声）视频片段
- `extract-video-frame`：截取视频中的特定帧
- `merge-video`：合并视频片段，添加过渡动画
- `change-fps`：帧率调整
- `split-audio`：分离视频中的音频
- `audio-gen-v3`：生成配音旁白(优先使用`video-gen`的原生音画同出生成能力，该技能仅作为质检不合格补充使用)
- `automatic-speech-recognition`：音频识别、为有人声视频添加台词字幕
- `get-output-dir`：获取输出目录保存中间文件和最终结果
