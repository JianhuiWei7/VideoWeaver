# One Sentence Anime Video Gen

## Overview
本技能专为短文本生成2D漫剧场景设计，用户仅需输入简短的核心剧情设定，即可自动扩展创作完整剧本，生成1分钟左右高质量、剧情连贯的2D动漫短剧，支持自定义动漫风格、画面比例等参数，确保视频中多次出现的人物、场景、物体等元素高度一致，符合动漫制作标准。

## 核心能力
1. 支持短文本输入（一句话核心设定），自动创作完整符合逻辑的1分钟动漫剧本
2. 自动生成符合动漫叙事节奏的分镜规划，适配1分钟左右的视频时长
3. 支持自定义2D动漫风格（古风、都市、奇幻、科幻等）、画面比例（9:16竖版、16:9横版等）
4. 自动维护元素一致性：角色形象、场景、道具、画风等在全片中保持统一
5. 自动匹配音效、背景音乐、配音、字幕，生成可直接使用的成片
6. 内置严格的一致性校验机制，确保生成内容符合用户需求

## 标准Plan.json Schema（保留）
```json
{
  "demand": {
    "original_text": "用户原始需求全文 + 核心设定全文（必须）",
    "demand_list": ["结构化提取的核心设定要点、剧情节点、角色要求、风格要求（必须，按优先级排序）"],
    "original_assets": ["用户提供的风格参考图、角色参考图路径（可选）"],
    "generated_assets": [
      "主要角色三视图（必须，每个角色独立生成）",
      "主要场景设定图（必须，每个场景独立生成）",
      "整体风格参考图（必须，统一画风）",
      "其他生成的辅助资产路径"
    ]
  },
  "shots": [
    {
      "shot_id": "镜头编号（必须，从1开始递增）",
      "description": "镜头详细描述，必须承接上一个镜头的剧情发展（必须）",
      "duration": "时长（秒，范围为4-15，必须）",
      "lines": "角色台词内容（可选，标注说话人、语气）",
      "subtitle": "字幕内容（可选，对应台词/剧情提示）",
      "shot_type": "连续镜头：与上一个镜头连续/切分镜头：与上一个镜头之间进行切镜（必须）",
      "require_assets": ["需要关联的资产ID（角色/场景/风格参考）"],
      "is_completed": "bool（必须，标记镜头是否生成完成）"
    }
  ]
}
```

## 工作流
#### 你必须严格按照以下1-6的步骤顺序执行，前置步骤未完成并输出结果前，绝对不允许提前执行后续步骤。

### 步骤1：需求解析与剧本创作
1. 读取用户提供的短文本输入，提取核心要素：
   - 核心剧情设定、角色设定、场景设定
   - 用户指定的视频风格、画面比例、细节要求
   - 提取出在多个视频片段中重复出现的角色、场景、道具等元素，用于生成一致性资产
2. **CoT思维链剧情创作**：
   - 基于核心设定自动扩展为完整的1分钟动漫剧本
   - 完善角色人设：为每个主要角色补充统一的外貌、服装、性格、说话方式设定，全程保持一致
   - 完善场景设定：明确剧情涉及的所有场景的外观、时间、天气、氛围设定
   - **对剧情进行有逻辑地扩写**，补充人物说话内容、具体事件和动作细节、背景音乐风格等，充分照顾视频生成所需的细节描述；生成符合上述标准Schema的空值`plan.json`文件、将扩写后的剧情写入`plan.json`的`demand.demand_list`的第一项

### 步骤2：分镜规划
#### 请确认步骤1已完成，提取出了所有核心要素并完成了资产评估。
1. 根据总时长和剧情结构，拆分视频为多个镜头（每个镜头时长4-15秒，总时长60±5秒）
2. 制定分镜计划，生成符合上述标准Schema的`plan.json`文件，使用`get-output-dir`获取的输出文件夹保存这个plan.json文件，包含每个镜头的：
   - 剧情内容（对应视频生成prompt）剧情要进行适当地扩写，特别是人物说话的内容，以及背景音乐的范围等
      1. prompt重写时，要对传入的参考资料的占位符进行重新排序，只考虑传入参考资料的顺序，从[图1]开始，每个图占一个位置。比如只传入了3张图，那么按照传入的顺序，在单次调用应该使用[图1]、[图2]、[图3]的顺序，不需要给未使用的参考图的占位。
      2. 如果参考图之间有相关联，那么在prompt中要说明，比如[图1]手中拿着[图2]; [图1]中的角色被绑在[图2]中。
      3. 补充，完善主体的说话内容，包括人物说话的内容，以及背景音乐的范围等。 使用格式：主体A说了: "xxx", 主体B说了: "xxx"
      4. 每一个镜头都需要说话内容，要丰富，多样，不重复。 
      5. 每一个镜头都需要考虑是否要加入背景音和旁白，来帮助读者了解场景、人物、事件等。
      6. prompt进行重写时，剧情内容和具体细节需要详细描述，不能笼统地表达。
   - 时长（秒）
   - 镜头类型（连续/切分）
   - 场景描述
   - 出场角色/物体
   - 需要使用的一致性资产
3. 分镜节奏符合动漫规律，每一个分镜里面的小段情节/故事要连贯，不能断层。比如：一个片段里，女主角摔倒了，男主角从后面扶住了她。是一个连贯的动作/事件，不能将他们拆分开成在第一个片段里面摔倒了，在第二个片段里面被扶住了。会导致视频生成的不连贯。

### 步骤3：一致性资产生成
#### 请确认步骤2已生成符合标准Schema的 `plan.json` 并保存到了输出目录。
1. 提取`plan.json`中所有的重复、多次出现的元素：角色、核心场景、关键道具、风格设定等
2. 为每个元素生成对应的一致性资产：
   - 角色：使用`image-gen`技能。生成统一的角色的三视(正面、侧面、背面)形象图，并且保持纯白背景图，可以在一张图中直接输出三视图
     - 一张图片中可以包含至多一个角色的三视图
     - 可以生成多个人物，主角，次要人物，配角等。生成的一致性资产越多，效果越好
   - 场景：使用`image-gen`生成统一的场景设定图。如果有多个场景，可以生成多个场景图。
   - 整体风格参考图：生成统一的画风参考，明确线条风格、上色方式、整体色调，全程保持画风统一
   - 音效/音乐：提前规划统一的音效风格和背景音乐
3. 所有一致性资产保存在任务输出目录中，并记录到`plan.json`的`generated_assets`字段，供后续片段生成复用

### 步骤4：分段四宫格剧情帧生成
#### 请确认步骤3中所有需要补充的角色、场景、风格等一致性资产已全部生成并保存到`plan.json`。如果未完成，请立刻停止当前步骤，返回步骤3。
1. 从`plan.json`中读取每个镜头的剧情内容，生成对应的四宫格图片。
2. 四宫格的生成需要选取：**每个镜头剧情相关的所有的一致性资产**并且**加上上一个剧情镜头的四宫格作为参考传入。**如果是第一个剧情镜头的四宫格，那么不需要加上上一个剧情镜头的四宫格。
3. 四宫格生成调用技能`image-gen`, 并且model必须要设置为`gpt-image-2`, `quality`设置为`auto`，`ratio`为1:1, prompt写上：生成一张4宫格漫剧分镜图片，展示这个剧本的整体走向。参考[图1]的xxx, [图2]的xxx, [图3]的xxx, [图4]的上一个剧情片段的四宫格。然后写上这个片段的剧本剧情。
4. **阶段性校验（必须执行）**：
   - 调用`vision-understanding`检查四宫格中的角色形象是否与参考立绘一致
   - 调用`vision-understanding`检查场景、风格是否符合要求
   - 校验不通过的重新生成

### 步骤5：分段生成视频
#### 请确认步骤4中每个镜头的四宫格剧情图片已生成完毕。如果未完成，请立刻停止当前步骤，返回步骤4。
#### 若不是第一个镜头，使用`split-audio`技能来分割上一个镜头音频
1. 按照分镜计划，逐段生成视频：
   - 使用`video-gen`技能生成每个镜头，传入**当前镜头的四宫格剧情图片**, **和当前镜头相关的所有的一致性资产**, **和上一个镜头的音频以作为参考，来保证风格统一**
   - 生成具体镜头前，确保prompt已经被重写。Prompt应该是：参考[图1]的整体剧情(这里的图1指的是4宫格的图片)，(图2到4指的是一致性资产的图片)以及[图2]的xxx, [图3]的xxx, [图4]的xxx, 生成xxx（prompt的剧情内容、台词和具体动作细节需要详细描述）。参考[音频1]的人物音色, 背景音乐，保持音频等元素的高度一致，剧情连贯，**禁止重复音频里说话的内容和背景音乐**。
   - 每个片段生成超时设置为60分钟，避免生成失败
4. **阶段性校验（必须执行）**：
   - 生成完成后使用`vision-understanding`检查：
     - 角色形象、服装、配色是否与参考图一致
     - 剧情内容是否符合镜头描述
   - 不符合要求的重新生成，更新`is_completed`状态到`plan.json`
   - 所有镜头校验通过后才能进入下一步

### 步骤6：视频合并与后期处理
#### 请确认步骤5所有分镜头视频均已成功生成并通过校验。如果还有缺失，立刻返回步骤5继续生成。
1. 使用`merge-video`技能将所有片段合并为完整视频，保证片段衔接流畅
2. 使用`change-fps`、`resize-video-resolution`调整视频参数符合要求（默认1080P 24帧）
3. 自动识别音频内容添加字幕，匹配剧情节奏，使用漫剧风格字体
4. **最终校验（必须执行）**：
   - 使用`vision-understanding`逐条校验`plan.json`中`demand_list`的所有需求点是否完成
   - 检查总时长是否符合用户要求（误差±5秒）
   - 检查角色、场景、风格在全片是否保持一致
   - 不合格则返工
5. 保存最终成片到`get-output-dir`获取的输出文件夹，命名为：`final.mp4`

## 依赖子技能
本技能依赖以下基础技能，执行过程中需直接调用：
- `image-gen`：生成角色、场景、风格参考等一致性资产图片，请使用`gpt-image-2`模型
- `video-gen`：生成单段视频内容
- `vision-understanding`：检查生成的视频/图片内容是否符合要求，校验一致性
- `extract-video-frame`：截取视频中的特定帧
- `merge-video`：合并多个视频片段
- `trim-video`：裁剪调整视频片段时长
- `get-output-dir`：获取任务输出目录路径
- `split-audio`：分离视频中的音频用于参考
- `change-fps`：视频帧率调整
- `resize-video-resolution`：视频分辨率调整
- `automatic-speech-recognition`：音频识别、为有人声视频添加台词字幕
- `audio-gen-v3`：生成角色配音（备选，仅在检查发现生成视频中无配音时使用）

## 注意事项
1. 元素一致性是核心要求：同一角色、场景、道具、画风在不同片段中必须保持完全一致，不得出现人设崩坏、场景突变、画风漂移等问题
2. 剧情必须连贯流畅，符合逻辑，无叙事断层，100%忠于用户提供的核心设定，不得随意篡改
3. 严格遵循plan.json标准Schema，所有必填字段必须完整填写
4. 总时长控制在60±5秒范围内，符合1分钟短剧要求
5. 所有生成过程的超时时间需设置足够长（单片段生成超时≥60分钟，总任务超时≥120分钟），避免任务中途失败
