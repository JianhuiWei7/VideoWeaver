`input` 主要用于整理原始输入，建议先生成 `input.json`。
`input` 里通常包含以下几类输入：
- `参考文本`
- `需求`
- `参考图片`

各类输入的职责：
- `参考文本`：通常用于描述品牌主张、产品卖点、参考旁白或展示逻辑，但不一定天然适合直接生成视频，因此这里主要先提取参考文本中的有效叙事信息、品牌信息和旁白信息
- `需求`：通常用于描述要生成什么样的视频，例如时长、风格、题材、氛围、是否要字幕或配音、是否有指定镜头顺序、是否有明确的品牌展示逻辑等
- `参考图片`：通常用于提供视频生成时需要参考的素材，不直接等于最终需求本身；这里要先判断它们分别能提供什么参考价值，例如品牌元素、风格、空间、节奏、镜头语言、音频氛围等

`input.json` 的职责是详细整理输入，而不是直接下执行结论。它应尽量忠实记录：
- 原始文本输入
- 参考素材路径
- 图片的理解结果
- 对文本输入的结构化拆解
- 适合视频生成的改写结果
- 模糊点和改写原因
- 用户已经明确指定的展示逻辑、镜头顺序、旁白要求和音频要求
- 哪些内容是品牌宣传片后续规划时必须优先遵守的输入前提

建议：
- 对 `参考图片` 调用 `video-understanding`，提取画面描述、品牌元素、人物/场景/物件信息，以及它更适合做品牌锚点、产品锚点、场景锚点还是风格锚点。
- 对 `参考文本` 和 `需求` 提取文本内容本身，并进行结构化整理，特别要识别：
  - 是否明确给出了品牌主张
  - 是否明确给出了展示顺序
  - 是否明确给出了旁白文案或口播要求
  - 是否明确给出了风格、节奏、景别、情绪要求

- `参考文本` 和 `需求` 可能都不够清晰。
- 品牌宣传片输入阶段不要急于把卖点一一映射成镜头，而应先整理出后续 `plan` 阶段真正要用的品牌主线、卖点层级、展示逻辑和音频要求。

`input` 阶段的目标不是直接生成分镜，而是先把混乱输入整理清楚，为后续提取真正的视频生成需求做准备。


`input.json` 示例：

```json
{
  "raw_inputs": {
    "需求": [
      {
        "path": "",
        "content": ""
      }
    ],
    "参考文本": [
      {
        "path": "",
        "content": ""
      }
    ],
    "参考图片": [
      {
        "path": "",
        "description": ""
      }
    ],
    "参考视频": [
      {
        "path": "",
        "description": ""
      }
    ]
  },
  "structured_understanding": {
    "品牌主张": "",
    "核心卖点": [
      ""
    ],
    "展示逻辑": [
      ""
    ],
    "旁白与音频要求": {
      "是否有全程旁白倾向": "",
      "是否有参考文案": "",
      "是否有BGM/音频氛围要求": ""
    },
    "优先遵守的输入前提": [
      ""
    ]
  }
}
```
