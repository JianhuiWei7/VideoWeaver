`shot` 主要用于根据 `plan.json` 生成更细的镜头拆解，建议产出 `shot.json`。

这里的 `shot.json` 是在 `plan.json` 基础上的逐镜头执行表，用来明确每个镜头具体拍什么、时长多长、是否连续、需要哪些资产，以及是否已经完成。

生成 `shot.json` 时，必须同时满足：
1. `requirement.json` 的硬性指标
2. `plan.json` 的整体规划
3. `asset.json` 中已经准备好的可用资产


`shot.json` 主要解决以下问题：
- 每个镜头具体拍什么
- 每个镜头对应哪个卖点或叙事任务
- 每个镜头时长如何分配
- 每个镜头是否与上一镜连续
- 每个镜头需要调用哪些资产
- 整条品牌宣传片如何避免离散堆砌和机械拼接

`shot.json` 采用如下核心结构：

```json
{
  "shots": [
    {
      "shot_id": "镜头编号（必须，从1开始递增）",
      "description": "镜头详细描述，必须明确对应哪个卖点、展示什么内容（必须）",
      "duration": "时长（秒，范围为4-15，必须）",
      "lines": "旁白内容（可选）",
      "subtitle": "字幕内容（可选）",
      "shot_type": "连续镜头：与上一个镜头连续/切分镜头：与上一个镜头之间进行切镜（必须）",
      "require_assets": ["需要关联的资产ID（可选）"],
      "is_completed": "bool（必须）"
    }
  ]
}
```

字段要求：
- `shot_id`
  - 必须从 `1` 开始递增
  - 不要使用跳号、重复编号或非顺序编号
- `description`
  - 必须写清楚这一镜具体展示什么
  - 必须明确它对应的卖点、品牌信息、使用场景或叙事任务
  - 品牌宣传片中，不能只写空泛氛围词，必须让人看得出这一镜在整条片中的作用
- `duration`
  - 单镜头时长范围为 `4-15` 秒
  - 所有镜头累计时长必须满足 `plan.json` 中的整体时长规划
- `lines`
  - 若品牌宣传片默认采用全程旁白，则应优先为每个镜头填写对应旁白
  - 若某镜头确实不需要旁白，可留空，但不能破坏整条片子的旁白连续推进
- `subtitle`
  - 仅在用户明确要求字幕，或该镜头确实需要屏幕文案时填写
- `shot_type`
  - 只能写两类：
    - `连续镜头`
    - `切分镜头`
  - 若该镜头需要延续上一镜的主体、动作、空间、情绪或音视频氛围，应优先标记为 `连续镜头`
- `require_assets`
  - 若该镜头需要引用 `asset.json` 中的品牌资产、产品标准资产、场景资产或桥接资产，应写对应资产 ID
  - 若没有明确依赖资产，可留空
- `is_completed`
  - 统一使用 `true / false`
  - 初始化时应为 `false`

提取规则：
- `shots` 的总时长必须与 `plan.json` 一致
- `shots` 的数量必须满足 `requirement.json` 或 `plan.json`
- 每个镜头都应服务于整体叙事推进，不能出现无意义 filler shot
- 每个镜头都必须明确对应一个卖点、品牌信息、体验节点或叙事任务，避免只堆砌画面元素
- 品牌宣传片中的镜头拆解应优先体现承接、递进、桥接和收束关系，而不是简单把每个卖点拆成一条独立广告镜头
- 若用户未明确指定完整分镜，镜头顺序应优先服从 `plan.json` 中的广告叙事主线、剧情主线和情绪主线
- 若任务采用品牌宣传片默认全程旁白方案，应尽量让 `lines` 与镜头一一对应推进，不应只在部分镜头出现旁白
- `shot_type` 应真实反映与上一镜的关系，不要为了方便全部写成同一种类型
- 若某镜头依赖品牌核心资产、产品标准资产、场景基础资产、续写锚点资产或桥接资产，应在 `require_assets` 中明确写出对应 ID

品牌宣传片额外要求：
- 默认避免把每个镜头都拆成独立闭环；镜头之间应保留连续空间，特别是开场到中段、中段到高潮、高潮到收束之间
- 默认避免在多个镜头里重复展示同一类信息，例如反复展示 logo、反复展示同一产品角度、反复展示同一人物动作
- 若某镜头属于品牌建立、产品证明、体验强化或价值收束中的关键节点，`description` 中应明确写出其在整条片中的作用
- 若某镜头承担桥接作用，应在 `description` 中明确写出它如何从上一镜过渡到下一镜
- 后续正式生成时，若 `shot_type = 连续镜头`，则默认应参考上一镜或上一段视频继续生成
- 在生成 `shot.json` 时，必须尽量清楚、具体地描述每个 shot 的内容，明确这一镜展示什么、对应哪个卖点或叙事任务，以及它在整条视频中的作用。
- 相邻 shot 之间的描述应保持明显区分，不得只是用不同措辞重复上一镜的主体、动作、构图或信息点；应通过卖点重点、景别、场景、动作、镜头作用或叙事位置体现差异。
注意：
- `shot.json` 不等于最终 prompt
- `shot.json` 不负责写最终生成命令
- `shot.json` 的作用是把整体规划拆成逐镜头执行依据
- `shot.json` 可以足够具体，但不要把每条镜头都写成完整 prompt 模板

因此，推荐顺序是：
1. `input.json`
2. `requirement.json`
3. `plan.json`
4. `asset.json`（若存在）
5. `shot.json`

简化版 `shot.json` 示例：

```json
{
  "shots": [
    {
      "shot_id": 1,
      "description": "开场镜头，建立品牌气质与主产品第一印象，对应品牌建立卖点，展示主产品 hero 形象与品牌空间氛围。",
      "duration": 8,
      "lines": "根据品牌主张填写开场旁白。",
      "subtitle": "",
      "shot_type": "切分镜头",
      "require_assets": ["A01", "A02"],
      "is_completed": false
    },
    {
      "shot_id": 2,
      "description": "承接上一镜，进一步展示产品核心卖点与使用场景，对应产品证明或功能优势卖点。",
      "duration": 8,
      "lines": "根据当前镜头内容填写对应旁白。",
      "subtitle": "",
      "shot_type": "连续镜头",
      "require_assets": ["A01", "A05"],
      "is_completed": false
    }
  ]
}
```
