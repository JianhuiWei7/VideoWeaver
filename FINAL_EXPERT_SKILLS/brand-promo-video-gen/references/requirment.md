在生成requirement.json前，一定要先阅读input.json
`requirment` 主要用于从 `input.json` 中提取硬性指标，并生成 `requirement.json`。
这里的 `requirement.json` 只放硬性要求，不放大段原始剧情，不放文学化描述，也不负责具体分镜执行。

`requirement.json` 重点提取以下内容：
- `时长`
- `分镜数`
- `分辨率`
- `宽高比`
- `fps`
- `是否有字幕`
- `是否有配音`
- `是否有音频`
- `输出文件名`
- `参考图片元素`
- `镜头要求`
- `风格要求`
- `画面要求`
提取规则：
- 优先读取 `input.json` 中已经整理好的输入理解结果。
- 只提取明确、可执行、可校验的硬性指标。
- 用户没有明确提出的，不要擅自补充，统一写 `没有`。
- `requirement.json` 是后续 `plan / shot / review` 的硬约束合同，不是原始输入备份。

注意：
- `参考文本` 和 `需求` 里的剧情内容，不应直接写入 `requirement.json`。
- 文学化表达、情绪表达、主题表达，通常不属于这里的硬性指标。
- 如果用户明确给了 `7个分镜`、`1分钟`、`720p`、`无字幕` 这类要求，可以提取。
- 如果用户给了 `参考图片`，可以提取参考图片中的关键元素，写入 `参考图片` 字段。
- 如果用户没有明确给分镜数、分辨率、fps 等，直接写 `没有`。

因此，推荐顺序是：
1. 先整理原始输入，生成 `input.json`
2. 再从 `input.json` 中提取硬性指标，生成 `requirement.json`

简化版 `requirement.json` 示例：

```json
{
  "硬性指标": {
    "时长": "",
    "分镜数": "",
    "分辨率": "",
    "宽高比": "",
    "fps": "",
    "字幕": "",
    "配音": "",
    "音频": "",
    "输出文件名": "final.mp4",
    "参考图片": "参考图片的元素",
    "参考视频": "参考视频的元素",
    "风格要求": "",
    "画面要求": "",
  }
}
```

如果用户没有明确给出，对应字段直接写 `没有`。
