# 视频生成与提示词优化统一技能（video-gen）

**环境依赖:** `openai`、`requests`、`tos`、`volcenginesdkarkruntime`
**⚠️警告: **: 不可以只将静态图片拼接来生成视频，必须调用本技能。


## 核心功能与工作流程
本技能整合了**提示词重写**、**视频生成**和**多轮日志记录**三大核心功能。**🌟 特别注意：本模型原生支持「音画同出」，即生成的视频可直接包含环境音、音效、配乐或角色台词！** 处理所有视频生成需求时，必须严格按照以下四大步骤依次执行：

---

### 第一步：提示词优化重写 (Prompt Rewriting)
对用户输入的视频生成提示词进行质量检查和优化重写，提升AI生成视频的效果和符合度。如果用户提供的prompt足够具体完整则直接返回，否则自动重写。

#### 1. 需求分析与素材处理
首先全面分析用户的视频生成意图与提供的素材：
- **需求意图识别**：判断用户是要生成全新视频、续写视频、补齐轨道，还是要求单镜头/多镜头等特定运镜效果。
- **参考素材处理**：
  - 若提供图片/视频：调用 `vision-understanding` 技能分析其内容、风格、动作、运镜等，作为重写的核心参考。
  - 若提供音频：提取节奏/驱动要求，并融入提示词描述中。
- **占位符检查**：确保提示词中正确引用了所有传入参考素材的占位符（如 `[视频1]`、`[图1]`、`[音频1]`）。
- **画面比例设定**：根据用户文本与参考素材的比例，来设定视频的比例。[详情见后文]
- **视频时长设定**：根据用户文本与参考素材的时长，来设定视频的时长。[详情见后文]
#### 2. 特定需求关键词映射
根据用户的具体需求，**必须**在提示词中加入相应的结构化关键词：
- **单镜头生成(single-shot video generation)**：如果要求单镜头生成，必须加入关键词 **全程单镜头** 或 **一镜到底**。
- **多镜头生成(multi-shot video generation)**：如果要生成多镜头的视频，必须在不同镜头的衔接处加上提示 **Shot cut** 或 **镜头切换**。
  > **注意**：如果没有明确指定单镜头，视频生成**默认为多镜头**。你需要根据用户的文本描述，推理出场景、视角或动作发生转换的合理位置，并在该处主动加入 `镜头切换` 或 `Shot cut`。
- **视频续写任务(video continuation)**：如果是续写视频，必须在提示词中加入关键词 **向后续写** 或 **向前续写**。
- **轨道补齐任务**：如果是轨道补齐，必须在提示词中加入关键词 **接**（例如：「视频1」+「过渡画面描述」+接「视频2」）。
- **音画同出 (自带声音生成)**：本模型支持视频与声音同步生成（音画同出）。若用户需要声音，**必须**在提示词中详细描述环境音、配乐或台词。句式通常为：「画面描述」，伴随着清晰的「环境音/配乐描述」，「角色」说：“「台词」”。
- **文字与字幕 (Slogan/Subtitle/Bubble)**：
  - **Slogan**：通用公式为：「文字内容」+「出现时机」+「出现位置」+「出现方式」，「文字特征（颜色、风格）」。若对文字表现效果要求严格，可结合多图参考。
  - **字幕**：画面底部出现字幕，字幕内容为“......”，字幕需与音频节奏完全同步。
  - **气泡台词**：「角色」说：“......”，角色说话时周围出现气泡，气泡里写着台词。
- **图片参考 (多图)**：
  - **多图参考**：句式通常为：参考/提取/结合/按照/生成+「图片n」中的「被参考元素描述」，生成「画面描述」，保持「被参考元素」特征一致。
  - **主体多视角图参考**：指代清楚参考对象即可。句式通常为：参考/提取/结合+「图片1-n」[1-n里的图是一个主体的不同视角]中的「主体」，生成「画面描述」，保持「主体」特征一致。
- **音频参考**：
  - **音色参考**：句式通常为：「角色」说：“「台词」”，音色参考「音频n」。
  - **音频内容参考**：句式通常为：理想出现时机+「音频n」。
- **视频参考 (动作/运镜/特效)**：
  - **动作参考**：句式通常为：参考「视频n」的「动作描述」，生成「画面描述」，保持动作细节一致。
  - **运镜参考**：句式通常为：参考「视频n」的「运镜描述」，生成「画面描述」，保持运镜一致。
  - **特效参考**：句式通常为：参考「视频n」的「特效描述」，生成「画面描述」，保持特效一致。
- **视频编辑 (元素增删改)**：
  - **增加元素**：在「视频n」的「时间位置」+「空间位置」，增加「理想元素描述」。
  - **删除元素**：删除「视频n」中的「被删除元素」，视频其他内容保持不变。
  - **修改元素**：将「视频n」中的「被更换元素描述」，替换为「理想元素描述」。
> **注意**：如果是视频编辑任务，输出视频的时长与ratio必须与原始视频一致。

#### 3. 视频生成模式分类与要求
根据用户提供的素材和意图，视频生成分为以下几种模式，重写提示词时需准确识别并遵循各模式的要求：
1. **Text2video (文生视频)**：用户仅提供文本描述，无任何图片或视频输入。对应参数：仅 `prompt`。
2. **Image2video (首帧/首尾帧生视频)**：意图是"让这张图动起来"、"从这张图开始生成"或"生成连接这两张图的视频"。在提示词中明确指定传入的参考图用作首帧或尾帧。对应参数：`reference_image` + 提示词指定。
3. **Reference image 2video (参考图生视频)**：意图是参考图片的风格、人物形象或内容。对应参数：`reference_image`。
4. **Reference video 2video (参考视频生视频)**：意图是参考视频的动作或风格。对应参数：`reference_video`。
5. **Reference video image to video (参考视频+图生视频)**：同时提及参考视频和参考图片（如"用这张图的人物复刻那个视频的动作"）。对应参数：`reference_video` + `reference_image`。
6. **Audio driven video (音频驱动视频/参考音频)**：参考音频的节奏、情感或将其作为驱动源。（**注意**：不支持单独参考音频，必须与视频或图片搭配）对应参数：`reference_audio` + `reference_video`/`reference_image`。
7. **Video extension (视频延长)**：意图是将现有视频向前或向后延长。对应参数：`reference_video` + 延长相关的 prompt 描述。
8. **Track filling (轨道补齐)**：拼接多个视频并补齐中间过渡。对应参数：多个 `reference_video` + 轨道补齐相关的 prompt 描述。

#### 4. 提示词质量评估与重写规则
当满足以下**所有**条件时判定为合格，直接返回原 prompt：
- 明确描述了核心主体及**动作/动态**；明确场景/背景；明确**运镜方式**；明确视频风格/光影；正确使用参考素材占位符。
- 所有传入的参考素材都必须要有占位符，并且在提示词中正确引用。
- 所有核心的事件都要有具体的描述，不能笼统地表达，越具体越好。

**重写后的结构模板**：
```text
[视频风格], [核心主体及动作描述]，[场景/背景描述]，[运镜/相机运动描述]，[光线/氛围描述]，[声音/配乐/台词描述(若需音画同出)]，[需要排除的负面元素]
```
- **核心优化原则**：动态优先（必须清晰描述主体动作幅度/速度和相机运动）、具体化描述、音画同步、占位符明确对应、补充优质参数（动作流畅，高帧率，电影级光效，高清画质）。
- **风格一致性**：视频的风格，如果用户指定了风格，那么必须使用用户指定的风格。如果没有指定风格，那么你可以从参考视频或参考图片中分析出风格，或从文本描述中分析出风格。
#### 5. 提示词重写示例
- **示例1：模糊 prompt 重写**（输入：`帮我生成一段猫喝水的视频`）
  > 重写后：现实风格, 一只橘色短毛猫正在低头喝水，舌头快速舔舐水面，水面产生细腻的涟漪，特写镜头，全程单镜头，背景是模糊的温馨客厅，阳光从侧面窗户洒入，逆光效果，毛发清晰可见，动作流畅。
- **示例2：带参考素材重写**（输入：`用这张图生成视频，让里面的人动起来，类似这个视频里的动作` 附图1视频1）
  > 重写前，你调用了vision-understanding技能，分析了[图1]的风格、人物形象和场景。然后使用素材的风格，作为要生成视频的风格。
  > 重写后：二次元动漫风格, 基于[图1]的人物形象和场景，复刻[视频1]中的舞蹈动作，人物肢体动作流畅自然，衣服随动作摆动，保持[图1]的二次元动漫风格，背景保持不变，镜头跟随人物移动，高清画质。
- **示例3：多镜头视频生成**（输入：`生成一个女孩在街上走，然后回头笑的视频`）
  > 重写后：现实风格, 全景镜头，一个年轻女孩走在繁华的霓虹灯街道上，背影，动作自然，环境光斑闪烁 镜头切换 特写镜头，女孩突然回头，露出灿烂的微笑，发丝随风飘动，眼神清澈，电影级光效。

### 第二步：生成视频 (Seedance 2.0 API)
根据确定的生成模式和优化后的提示词，调用底层脚本执行生成。

#### 2. 支持模式
**1. 单任务生成模式（默认模式）**
指定参考视频、参考图片、提示词，生成单个视频。
**2. 批量处理模式（使用 --batch 激活）**
自动遍历输入目录下的分类文件夹，批量生成视频。

#### 3. 参数说明
| 参数名 | 说明 |
|--------|------|
| `--session-key` | **(Optional; OpenClaw Required)** 输出目录 session-key。CodeX/Claude Code 环境会自动识别，不需要传入内容；OpenClaw 环境必须运行 `session_status` 获取session-key并且传入, 格式通常为 `agent:{agent_id}:{session_id}`。 |
| `--batch` | 启用批量处理模式，不执行单任务 |
| `--prompt` | 单任务模式：生成提示词，支持`[视频1]`/`[图1]`/`[音频1]`占位符对应传入的视频/图片/音频顺序 |
| `--reference-video` | 参考视频路径。**支持传入多个参考视频，多次使用 `--reference-video` 参数即可（如 `--reference-video a.mp4 --reference-video b.mp4`）**。（**注意**：支持0~3个，单个视频时长2~15s，总时长≤15s，仅支持480p/720p，格式mp4/mov，单文件≤50MB） |
| `--reference-image` | 参考图片路径。**支持传入多张参考图片，多次使用 `--reference-image` 参数即可（如 `--reference-image a.jpg --reference-image b.jpg`）**（作为参考风格/内容，或指定首/尾帧）。（**注意**：支持0~9张，格式jpeg/png/webp/bmp/tiff/gif，单文件≤30MB） |
| `--reference-audio` | 参考音频路径。**支持传入多个参考音频，多次使用 `--reference-audio` 参数即可（如 `--reference-audio a.mp3 --reference-audio b.mp3`）**（作为音频驱动/节奏参考）。（**注意**：支持0~3个，单个音频时长2~15s，总时长≤15s，格式mp3/wav，单文件≤15MB） |
| `--output` | 输出视频文件名（**仅需文件名**，不要包含完整路径，会自动保存到 session 目录） |
| `--ratio` | 输出视频比例，默认16:9。支持 16:9, 4:3, 1:1, 3:4, 9:16, 21:9, 你需要根据用户文本与参考素材的比例，设定视频的比例。 |
| `--resolution` | 输出分辨率，默认480p，支持480p/720p/1080p |
| `--duration` | 生成视频时长，支持4-15秒。设置规则：1. 若用户文本中有指定，使用指定时长(高优先级)；2. 若未指定，需推理所需时长：如果是视频编辑任务，生成时长需与原始视频相等(你需要先获取原视频的时长)；如果是参考图片生视频且未指定时长，则设定为默认值（5秒）。 |
| `--model` | 模型名称，默认`doubao-seedance-2-0-fast-260128` |
| `--poll-interval` | 任务轮询间隔秒数，默认10 |
| `--background` | 在后台运行任务并返回JSON状态信息（不阻塞当前进程） |

#### 4. 重要参数设定
**1. 模型版本 (`--model`)**
| 模型名称 | 说明 | 适用场景 |
|---------|------|---------|
| `doubao-seedance-2-0-260128` | 标准模型，画质与细节表现更好 | 最终成片、高质量视频生成 |

**2. 分辨率 (`--resolution`)**
仅支持以下分辨率设置：
- `480p` (默认)
- `720p`

**3. 视频比例 (`--ratio`)**
支持以下画面比例：
- `16:9` (横屏)
- `9:16` (竖屏，适合短视频)
- `4:3` / `3:4`
- `1:1` (正方形)
- `21:9` (宽银幕)
> 你必须遵守以下设定规则:
> 1. 如果用户文本里有指定，就使用文本里指定的比例(高优先级)。 2. 如果没有指定，查看是否有参考视频/参考图片，如果有，就参考参考资料的大多数比例。如果没有参考视频/参考图片，就使用默认比例。

**4. 生成时长 (`--duration`)**
- 范围：4-15秒。
- 设置规则：
  1. 如果用户文本里有指定，就使用文本里指定的时长(高优先级)。
  2. 如果没有指定，需要推理出所需时长：如果是视频编辑，生成的时长**必须**与原始视频相等(你需要先获取原视频的时长)；如果是视频参考任务, 生成的时长可以与原始视频相等，根据情况判断；如果是参考图片，并且没有时长指定，那么设定为默认值（5秒）。
  自定义：可通过 `--duration <秒数>` 指定，例如 `--duration 10`。

#### 5. 参数配合说明
- **素材组合支持**：支持只参考图片、只参考视频、组合参考图片+视频、组合参考音频+视频、组合参考图片+音频、组合参考音频+图片+视频。
- **音频限制**：**不支持单独参考音频**，参考音频时必须与视频或图片搭配。
- **进阶组合用法（首尾帧控制）**：不再使用单独的首尾帧参数。可以同时上传图片、视频、音频，同时**通过 prompt 指定其中的参考图用作首/尾帧**。

#### 7. 执行规范
- **提交与响应**：提交任务后，必须等待脚本返回状态。只有在返回 `"running" 或者是 queued"` 时才认为任务成功挂起。如果返回错误，必须分析并修正重试。
- **进度轮询**：任务成功挂起后，使用 poll process，设置超时时间为 5 分钟 -> 如果还在 running -> 再 poll process 设置超时时间为 5 分钟 -> 直到生成完毕。

### 第三步：多轮迭代与日志记录 (Logging)
为了支持多轮迭代生成（例如：根据用户指令自动引用前n-1轮生成的视频作为参考进行动作延续、风格迁移或局部修改），在视频生成成功后，**必须**调用 `scripts/logging_manager.py` 记录本轮信息。
⚠️ **注意：如果手动传入 `--session-key`，调用 `logging_manager.py` 时需要与生成视频时保持一致；CodeX/Claude Code 环境会自动识别，不需要传入内容。**

**1. 记录本轮日志**：
脚本会自动保存到 `.../videos/multi-turn-video-log.json`
```bash
python video-gen/scripts/logging_manager.py --session-key "agent:{agent_id}:{session_id}" add --data '{
  "original_prompt": "[用户原始输入]",
  "rewritten_prompt": "[优化后的prompt]",
  "params": "[分辨率、时长、种子等参数]",
  "reference_videos": "[参考视频路径列表]",
  "reference_images": "[参考图片路径列表]",
  "generated_video": "[生成的视频路径]",
  "notes": "[备注信息，如生成模式]"
}'
```

**2. 获取历史记录**（用于基于历史生成的视频进行迭代修改）：
```bash
python video-gen/scripts/logging_manager.py --session-key "agent:{agent_id}:{session_id}" get
```
