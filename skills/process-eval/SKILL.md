# 任务评估技能 (Task Evaluation)

## 🎯 技能描述
当用户需要评估由 Agent 执行的任务时，请调用本技能。在调用时，你将会收到以下核心上下文：
1. **任务输入**：即用户的原始需求与约束条件。
2. **待评估的 Rubrics**：这是一系列预定义的评估标准，用于判断 Agent 执行任务的过程与结果是否符合要求。
3. **任务执行过程**：包括 Agent 执行该任务的完整步骤、工具调用记录。
4. **任务执行的最终结果**：包括 Agent 执行该任务的最终输出、生成的文件等。会以目录的形式提供。


## 🛠️ 可用关联技能
在进行评估时，你**应该调用或检查**现有的多个**视觉/音频相关技能**，以帮助你更准确地检查生成的媒体内容。包括但不限于：

- **视频处理与分析**：`vision-understanding`, `get-video-metadata`, `video-shot-split`, `video-gen`, `merge-video`, `trim-video`, `extract-video-frame`, `change-fps`, `resize-video-resolution`
- **图像处理与分析**：`image-gen`, `get-image-metadata`, `resize-image-resolution`
- **音频处理**：`trim-audio`, `split-audio`, `automatic-speech-recognition`
- **系统辅助**：`get-output-dir`

## 📚 领域背景知识 (视频生成)
在评估视频生成任务前，你**必须**读取以下文件：
- **文件路径**：`process-eval/references/video_generation_expertise.md`
- **说明**：该文件存储了视频生成的核心领域背景知识，包括一致性资产 (Consistent Assets)、一致性生成、长视频生成、多镜头生成等关键概念。

## 📊 核心评估标准 (Rubrics)
你可能会收到基于以下维度的 Rubrics，请严格按照对应的评估方法进行打分：

- **指定技能是否被调用**
  - **评估方法**：检查 Agent 的执行过程日志，确认其是否在任务初期的较前阶段读取了指定的 skill 文件夹或知识库。
- **指定技能调用步骤是否完整无缺漏**
  - **评估方法**：检查 Agent 的执行过程日志，确认其在执行任务时是否按照指定的 skill 中的流程一步一步执行, 没有跳步, 遗漏.
  - **分数**：无遗漏,正确执行的步骤数 / 总步骤数
- **输出目录合规性**
  - **评估方法**：检查 Agent 的执行过程日志，输出的要保存的资料，包括但不限于文件，视频、音频、图片等，是否都在同一个文件夹下面。
  - **分数**：正确保存次数 / 总输出次数
- **生成过程错误次数**
  - **评估方法**：检查 Agent 的执行过程日志，统计在调用各项工具/技能时，出现 error 报错的总次数。
  - **说明**：如果调用的错误不是自己参数设定的错误，而是其他原因导致的错误，如网络问题、资源不足等，这些错误不计入错误次数。
  - **分数**：调用无error次数 / 总调用次数
- **分镜片段合并**
  - **评估方法**：检查 Agent 的执行过程日志，确认是否调用了 `merge-video` 技能将多个生成的视频片段进行合并,或者也可以自己使用其他方法将视频合并。这一步骤一般发生在任务执行的最后几步。
  - **注意**：如果 Agent 没有调用 `merge-video` 技能，或者调用 `merge-video` 技能后，视频片段没有被合并，也算失败。最终的视频可能在任务执行最后生成的内容所在文件夹下面或其videos文件夹下面, 命名可能为为`final.mp4`, 或是 以 `merged`, `final` 开头的视频文件。
- **生成前规划**
  - **评估方法**：检查 Agent 的执行过程日志，确认在生成任何实质性内容前，是否输出了明确的规划（支持 `.json` 格式或纯文本格式，不强制要求输出为独立文件）。如果不规划就直接生成视频，则score为0
- **一致性资产准备与利用**
  - **评估方法**：检查 Agent 的执行过程日志，检查在生成视频前，Agent 是否使用了用于保持一致性的资产（如参考图、风格垫图等，资产可由用户提供或 Agent 自行生成）**或** 在视频生成过程中，是否使用了之前生成的片段作为一致性参考资产传入。
- **输入预处理**
  - **评估方法**：检查 Agent 的执行过程日志，确认是否在生成视频前对用户提供的多模态素材（如人物参考图片、参考音频、参考视频等）进行了理解和预处理，且将预处理结果作为生成参考使用。预处理需要使用skill来完成。比如使用`vision-understanding` skill对人物参考图片进行理解，使用`automatic-speech-recognition` skill对音色参考音频进行理解。也有使用 `trim-video`对视频进行分割。只要做了其中一个理解或预处理，就算完成了输入预处理, score为1.
- **技术规格达标**
  - **评估方法**：检查 Agent 交付的最终视频合并结果，先找到最终视频的路径，然后调用 `get-video-metadata` 技能来提取视频的技术参数（如 Aspect Ratio、Duration、分辨率等），并判断其是否符合原始需求。
  - **拆分输出**：如果一个Rubrics内提及了多个指标，你需要将每个指标拆分成更细的指标，每个指标都有自己的分数和反馈。
  - **时长分数**：(|生成的视频时长-要求时长| / 要求时长); 时长可以允许2秒之内的误差。
  - **画幅分数**：1 if 生成的视频画幅与要求的画幅一致 else 0;
  - **分辨率分数**：1 if 生成的视频分辨率与要求的分辨率一致 else 0;

## 📝 评估输出规范
在完成所有维度的评估后，你必须严格按照以下要求输出结果：

1. **补全 JSON 数据**：将接收到的 JSON 格式的 Rubrics 中空缺的 `score` 和 `feedback` 字段补充完整。
   - `score`：取值仅限默认为 `0` 或 `1`（`0` 表示低分/未达成要求，`1` 表示达标/满分）**或**是按照特殊需求要求进行打分，分数范围是 `0-1`。
   - `feedback`：必须使用**中文**提供具体的自然语言反馈，并引用执行过程中的具体证据。
2. **保存评估结果**：将补全后的结果格式化并写入名为 `rubrics_eval.json` 的文件中。你**必须使用** `process-eval/scripts/write_to_json.py` 脚本来完成写入，以确保 JSON 格式正确并支持中文。该脚本会自动获取当前 session 的输出目录。
   - **获取 session_key（仅 OpenClaw 必需）**：OpenClaw 环境必须运行 `session_status` 获取session-key并且传入, 格式通常为 `agent:{agent_id}:{session_id}`。
   - **注意事项**：CodeX/Claude Code 环境会自动识别，不需要传入内容。
   - **使用示例（通过参数传递数据，注意转义）**:
     ```bash
     python process-eval/scripts/write_to_json.py --output_filename rubrics_eval.json --session_key "agent:{agent_id}:{session_id}" --data '{"case_id": "xxx", "process_rubric": [{"id": "P0", "score": "1", "feedback": "表现良好"}]}'
     ```
3. **完成任务**：文件保存成功后，即可结束评估。
