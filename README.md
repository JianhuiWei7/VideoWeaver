# VideoWeaver: Evaluating and Evolving Skills for Agentic Long Video Generation

> Code workspace for **"VideoWeaver: Evaluating and Evolving Skills for Agentic Long Video Generation"**.

VideoWeaver studies whether general-purpose agent frameworks such as **Codex**, **Claude Code**, and **OpenClaw** can perform long-horizon video generation. Instead of using a fixed, human-written video pipeline, VideoWeaver gives an agent a library of reusable **foundation skills** and asks it to create, execute, evaluate, and evolve higher-level **composition skills** for long video generation tasks.

## About

Long video generation is not a single model call. A realistic task often requires the agent to understand multimodal references, plan multiple shots, generate images/videos/audio, preserve characters and scenes across clips, synchronize audio and visuals, and finally merge everything into a coherent `final.mp4`.

This repository contains:

- a set of **foundation skills** in `skills/` for media generation, understanding, editing, and evaluation;
- an agent harness in `AutomaticSkillOptimization/` for asking models to create task-level composition skills, running long-video generation cases, evaluating execution traces and final videos, and evolving generated skills from feedback;
- adapters for **OpenClaw**, **Codex**, and **Claude Code** execution environments.

## Skill Evolution Pipeline

<img width="1000" alt="Skill evolution pipeline" src="asset/pipeline.png" />

The execution agent first performs task inference: it asks the model to create category-level composition skills, then runs cases to collect execution traces, generated outputs, and evaluation feedback. The optimizer agent progressively refines the model-created composition skills and isolated creator-skill copies from these cases. Finally, the merge agent integrates category-level creator copies into a single improved creator.

## Evidence-Grounded Evaluation Pipeline

<img width="1000" alt="Evidence-grounded agent-as-judge evaluation pipeline" src="asset/eval.png" />

Given the user request, reference assets, execution trace, intermediate artifacts, and final video, the evaluation agent conducts a multi-turn evaluation. It dynamically invokes evaluation skills to inspect traces, extract metadata, sample key frames, separate audio, run ASR, analyze errors, and understand visual/audio content. The collected evidence is used to score process and output metrics with textual feedback.

The key idea is to separate basic capabilities from workflow knowledge:

- **Foundation skills** expose atomic operations such as `video-gen`, `image-gen`, `merge-video`, `automatic-speech-recognition`, `extract-video-frame`, and `output-eval`.
- **Skill creator skills** are also located under the `skills/` foundation-skill folder. In particular, `skill-creator` and `video-skill-creator` are foundation skills used to ask the model to author new workflows.
- **Composition skills** are not pre-existing foundation skills in this repository. They are generated by the model during experiments for specific task categories, and they describe how to orchestrate foundation skills.
- **Skill evolution** refines generated composition skills and the creator skills using execution traces, final outputs, and judge feedback.

## Key Contributions

- **Agentic long video generation benchmark**: VideoWeaver evaluates general-purpose agent harnesses on long video generation tasks that require multimodal input understanding, multi-step planning, and cross-clip consistency.
- **Foundation skill workspace**: The repository provides a library of reusable video, image, audio, media-processing, and evaluation skills that agents can invoke independently.
- **Composition skill workflow**: Agents create category-level composition skills during experiments, converting foundation skills into reusable long-horizon workflows.
- **Evidence-grounded agent-as-judge**: The evaluation framework inspects both execution traces and final videos, using tools to gather evidence such as metadata, keyframes, ASR transcripts, audio analysis, and intermediate artifacts.
- **Skill evolution pipeline**: The optimization code progressively refines model-created category composition skills and optimized copies of the creator foundation skill, then merges the learned creator copies into a single improved creator.
- **Multi-harness comparison**: The code supports OpenClaw, Codex, and Claude Code pipelines for comparing different agent runtimes and backbone models.

## VideoWeaver Pipeline

VideoWeaver follows three main stages.

### 1. Task Inference

For each dataset category, the execution agent uses a creator skill from the `skills/` foundation-skill folder and the rest of the foundation skill library to create an initial composition skill. That composition skill is generated during the run. The agent then runs each case by invoking the generated composition skill and foundation skills, producing:

- `final.mp4`
- intermediate images/videos/audio
- `ReAct_process.json`
- `ReAct_process.txt`
- `basic_results.json`

### 2. Evidence-Grounded Evaluation

The evaluator scores both the process and the final output.

Process metrics include execution errors, clip merging, input processing, planning, skill following, and reference asset usage.

Output metrics include format requirements, prompt requirements, visual consistency, audio consistency, audio-video consistency, plot logic, and reference fidelity.

### 3. Skill Evolution

The optimizer reads task inputs, execution traces, generated artifacts, and evaluation feedback. It updates the model-created category composition skill and an isolated copy of the creator foundation skill. After all categories are optimized, those category-level creator copies are merged with `pair-wise-skill-merge`.

## Installation

Install Python dependencies:

```bash
python -m pip install -r requirements.txt
```

Install system media tools separately:

```bash
ffmpeg
ffprobe
```

Common environment variables:

```bash
export ARK_API_KEY="..."
export TOS_ACCESS_KEY="..."
export TOS_SECRET_KEY="..."
export ASR_APPID="..."
export ASR_TOKEN="..."
export APP_ID="..."
export APP_SECRET="..."
export DEEPSEEK_API_KEY="..."
```

For OpenClaw, see [OpenClaw_Setup.md](OpenClaw_Setup.md). The setup helpers in `AutomaticSkillOptimization/args.py` can populate the OpenClaw workspace and update skill loading paths, but credentials and local paths should be checked manually.

## OpenClaw Configuration

The OpenClaw pipeline requires extra environment and workspace settings before running `AutomaticSkillOptimization/inference_OpenClaw/pipeline.py`. In particular, you need to configure OpenClaw skill loading paths, output directory variables, API credentials, execution approvals, and long-running timeout limits.

Please follow [OpenClaw_Setup.md](OpenClaw_Setup.md) before launching OpenClaw experiments.

## Dataset Format

The pipelines expect a dataset directory with task categories and case folders:

```text
dataset/
└── <task_category>/
    ├── skill_query.json
    ├── <case_id>/
    │   ├── *.txt
    │   ├── reference images/videos/audio
    │   └── rubric_deterministic.json
    └── ...
```

`skill_query.json` defines the composition skill to create for that category:

```json
{
  "skill_name": "your-composition-skill-name",
  "skill_query": "Instructions for creating the category-level composition skill."
}
```

Case folders can include `.txt`, image, video, and audio files. The pipeline converts them into the generation prompt and passes file paths to the agent.

## Usage

Always run with `--dry_run true` first to inspect the execution plan.

### Run Codex Generation

```bash
python AutomaticSkillOptimization/inference_CodeX/pipeline.py \
  --dataset dataset \
  --target_task all \
  --skill_type expert \
  --max_concurrency 5 \
  --test_sample 9999 \
  --dry_run true
```

Execute:

```bash
python AutomaticSkillOptimization/inference_CodeX/pipeline.py \
  --dataset dataset \
  --target_task all \
  --skill_type expert \
  --max_concurrency 5 \
  --test_sample 9999 \
  --dry_run false
```

### Run OpenClaw Generation and Process Evaluation

```bash
python AutomaticSkillOptimization/inference_OpenClaw/pipeline.py \
  --agent_id main \
  --dataset dataset \
  --target_task all \
  --skill_type expert \
  --max_concurrency 20 \
  --test_sample 40 \
  --dry_run true
```

Set `--dry_run false` to launch the full OpenClaw run.

### Run Claude Code Generation

```bash
python AutomaticSkillOptimization/inference_ClaudeCode/pipeline.py \
  --dataset dataset \
  --target_task all \
  --skill_type expert \
  --claude_backend deepseek \
  --dry_run true
```

## Skill Strategies

The generation pipelines support several experiment modes:

- `--skill_type expert`: use `skills/video-skill-creator` to ask the model to create video-specific composition skills.
- `--skill_type vanilla`: use the general `skills/skill-creator`.
- `--no_composition_skills true`: baseline where the agent only has foundation skills.
- `--create_skill_only true`: create composition skills without running generation cases.
- `--use_existing_skill_dir true --existing_skill_dir <dir>`: reuse composition skills created by a previous run.
- `--use_existing_skill_creator true --existing_skill_creator_dir <dir>`: ask the model to create new composition skills with an optimized creator skill.

## Evaluation

### Process Evaluation

Run evaluation on existing generation results with the `process-eval` skill:

```bash
python AutomaticSkillOptimization/evaluation_PRM/evaluate_PM+FR.py \
  --dataset dataset \
  --result_dir <generated_result_dir> \
  --target_task all \
  --limit 0 \
  --dry_run true
```

### Output Evaluation

Run final-video evaluation with the `output-eval` skill:

```bash
python AutomaticSkillOptimization/evaluation_ORM/evaluate_OM.py \
  --result-dir <generated_result_dir> \
  --dataset-dir dataset \
  --limit 0 \
  --dry-run true
```

Evaluation outputs include rubric files, evidence sidecars, execution-error reports, and aggregate summaries.

## Skill Evolution

The main optimizer is `AutomaticSkillOptimization/optimize/CodeX_GPT_optimize_skill.py`.

Dry run:

```bash
python AutomaticSkillOptimization/optimize/CodeX_GPT_optimize_skill.py \
  --dataset_dir dataset \
  --task_result_dir <generated_result_dir> \
  --composition_skill_dir <composition_skill_dir> \
  --creator_skill_dir skills/video-skill-creator \
  --split_name train \
  --eval_source both \
  --dry_run true
```

Execute:

```bash
python AutomaticSkillOptimization/optimize/CodeX_GPT_optimize_skill.py \
  --dataset_dir dataset \
  --task_result_dir <generated_result_dir> \
  --composition_skill_dir <composition_skill_dir> \
  --creator_skill_dir skills/video-skill-creator \
  --split_name train \
  --eval_source both \
  --dry_run false \
  --resume true
```

`--eval_source` controls the feedback source:

- `none`: self-evolution from objectives only.
- `llm`: use PRM feedback from process/trace evaluation.
- `human`: use ORM feedback from output/video evaluation.
- `both`: use both PRM and ORM feedback.

## Outputs

Default paths are defined in `AutomaticSkillOptimization/args.py`:

```text
generate_materials/              # Active generation outputs
generate_materials_failed/       # Failed sessions
generate_materials_half_stopped/ # Interrupted sessions
running_logs/                    # Runtime logs
<exp_id>/                        # Archived experiment outputs
```

A completed generation session usually contains:

```text
final.mp4
ReAct_process.json
ReAct_process.txt
basic_results.json
evals/
rubric_eval_detail.json
```

Optimization archives include optimized model-created composition skills, category-level creator-skill copies, diff reports, progressive merge outputs, and a manifest file.

## Notes

- Codex and Claude Code use private workspace copies so experiments do not mutate the source `skills/` directory.
- OpenClaw may modify loaded skills, so the setup and cleanup code copies/restores skill directories carefully.
- The pipelines are designed for long-running jobs and include retry, resume, failed-session, and half-stopped-session handling.
- `requirements.txt` covers Python packages. `ffmpeg` and `ffprobe` must be installed separately.

## Language Support

The current version supports Chinese-language tasks and prompts. English-language support will be developed in a future version.
